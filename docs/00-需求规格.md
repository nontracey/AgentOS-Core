1. 需求 ID 一经分配**不再复用、不再重排**；废弃需求标记 `退役` 而非删除，保留可追溯性。

## 1. 项目目标与定位

AgentOS 是可自托管的 AI 集成与治理底座：连接企业散落的模型、Agent、知识、技能、工具、身份与既有业务系统，统一任务、权限、审批、成果和用量。个人工作台是首个入口；核心与能力按需装配，部署不绑定设备、操作系统或固定机器数量；企业已有能力通过适配器接入，不强制替换企业原有系统。企业额度分配、旧项目管理和真实 IM 实现后置，接口先纳入设计。

产品的长期能力目录与当前版本分别管理。需求编号和完整验收阈值由本文维护；实施范围、完成程度和待完成事项统一见 [开发计划](04-开发计划.md)。

### 1.1 一句话目标

> 构建一套**入口归一、既有 Port 实现可换、治理横切**的 Agent 底座：个人能拿来当「个人任务执行平台」，企业能拿来当「组织任务执行平台」。替换既有能力实现不改内核调用方；新增能力或破坏性契约变更须版本化 Port 与迁移。两种形态共用可兼容的 Port 契约与技能资产。

### 1.2 三个视角的成功定义

| 视角 | 成功条件 | 失败表现 |
| --- | --- | --- |
| **个人 / 一人公司** | 手机或桌面网页提交需求与素材，系统自动规划、分派适合的 Agent，并调度具备能力的电脑执行；交付可查看、下载、修改的结果，必要时向本人澄清或请求审批 | 只给建议和计划，仍须本人逐个找 Agent、选电脑、复制素材和汇总结果 |
| **企业（≤100 人）** | 在同一代码与 Port 契约上启用企业身份、权限范围、审批、审计、成本归集；单机可跑、组件少、挂了能恢复 | 引入了多租户/计费等大厂复杂度，没人运维得起 |
| **工程质量** | 架构取舍、失败模式、成本和治理边界有可复核证据 | 仅有组件清单，缺少行为验证与运行记录 |

### 1.3 人与系统的工作分工

owner 提交目标、约束与素材，补充会影响结果的必要信息，检查成果并提出修改；在已授权范围内不需要逐步确认普通动作。系统负责拆解依赖、选择角色/技能、分配工具与电脑、传递产物、跟踪进度、失败恢复和汇总。需求不明确时针对关键歧义提问，普通可逆选择采用可见默认值。

例：“用这些素材生成一段 30 秒视频，先出预览，预算不超过指定额度。”系统可安排策划 Agent 形成脚本，制作 Agent 通过具备视频生成能力的授权节点执行，检查 Agent 核对格式/时长/内容，最终回传预览、文件和未决项。角色按任务需要组合，简单任务可以一个 Agent 完成。设备与操作系统只来自具体任务约束，不能据此假定节点已安装生成器、模型或具备足够显存；开工时探针确认。

Agent 是逻辑工作角色，Node 是实际执行资源；一个 Agent 可调用多台电脑，一台电脑可承载多个受配额限制的任务。模型可在网关、授权云端或推理节点，工具执行地点由资源调度独立决定。具体业务系统不参与这一主链路的完成判定。

### 1.4 非目标

| 非目标 | 原因 |
| --- | --- |
| 自研大模型 / 训练 | 成本与周期不可控，模型是可替换的能力源 |
| 自研插件协议代替 MCP | 违反「优先用开源开放标准」原则（SRC-05、SRC-19） |
| 多租户计费 / SaaS 运营 | 超出当前目标，增加不必要的运维和产品复杂度 |
| 微信个人号协议机器人 | 封号风险，微信在本系统中只作为通知接收端 |

## 2. 术语表

| 术语 | 含义 |
| --- | --- |
| **Port** | 内核定义的**能力接口**（隔离后端差异），只描述最小能力契约，不绑定任何实现 |
| **Adapter** | Port 的具体实现，吸收后端产品差异；Port 契约变化还需版本化、兼容测试与数据迁移 |
| **契约测试（Conformance Suite）** | 同一份测试跑遍某 Port 的所有 Adapter，全绿才允许接入 |
| **Envelope** | 所有入口统一后的内部消息结构（身份 / 上下文 / 幂等键 / 附件） |
| **Skill** | 符合 Agent Skills 开放标准的 `SKILL.md` 技能单元，三段式渐进加载 |
| **Node Agent** | 每台机器上的守护进程，代表该机提供本机算力与能力，负责任务队列与离线续跑 |
| **Decision Port** | 快决策层（System One 形态），输入 state+questions、输出 choice/score/noul 及题型对应概率信息，与 Model Port 契约形状完全不同 |
| **noul / choice / score** | System One 的三种题型原语：`noul` 返回「是」的 0–1 概率（无独立 confidence 字段）；`choice` 返回选中项 + 全概率分布 + confidence；`score` 返回有序等级的加权分数 + legend + 分布。内部契约必须能表达三者，不能简化为 `prompt/options/choice` |
| **Kev / Laya / Jev** | System One 的三种候选决策后端：Jev 为托管服务；Kev 明确指 jaredpalmer/kev；Laya 为另一自托管实现。API 路径兼容不代表全部题型、质量与性能等价；按锁定版本和中文业务样本验证，详见决策核对记录 |
| **HITL** | Human-in-the-loop，人工审批/介入节点 |
| **ADR** | Architecture Decision Record，架构决策记录（含退出成本） |
| **RTM** | Requirements Traceability Matrix，需求追踪矩阵 |
| **逻辑步骤 ID** | 一次业务意图中的一个具体执行步骤；同一步重试沿用该 ID，两次合法的相同操作使用不同 ID |
| **授权上下文** | 经入口验证的主体、组织、资源范围、角色、会话与请求目的；知识、记忆、工具、节点均据此做服务端授权 |

## 4. 功能需求

**优先级标记**：`M`=最终能力目标必需，`S`=应交付，`C`=可选增强，`W`=不做。这些标记不等同当前实施范围；近期任务映射见 §11，完整条目未满足时保留 partial/gap。近期交付单机或按需一个执行节点的个人任务闭环与专业响应式工作台，远期逐步完善企业、多机、移动离线及更多后端。

### 4.1 FR-ING 入口与渠道适配

| ID | 需求 | 优先级 | 验收判据 |
| --- | --- | --- | --- |
| FR-ING-01 | 支持多渠道入口：CLI、HTTP API、移动端/PWA、语音、邮件、Cron/Webhook，且可继续新增 | M | 至少 4 类入口可用；新增一类入口**不改 kernel/runtime 代码** |
| FR-ING-02 | 所有入口进入后归一为统一 `Envelope`（身份 / 会话上下文 / 幂等键 / 附件引用） | M | kernel 只接收 Envelope；任意入口的消息可在同一会话中接续 |
| FR-ING-03 | 入口层必须在 sink 之前完成：适用渠道的签名/令牌校验、幂等去重、附件安全落盘、身份解析；未经验证不得形成可执行 Envelope | M | 同一渠道事件 ID 重放返回原受理结果；伪造签名、超范围附件、未认证身份分别被拒并记审计 |
| FR-ING-04 | 新增一个入口的实现工作量小于半天 | S | 实测：写一个新 `IngressPort` 实现类后全链路可用 |
| FR-ING-05 | 入口身份与外部渠道账号解耦，映射为内部 subject（便于未来换 SSO） | S | 更换身份提供方只改身份 Adapter/配置，channel adapter 与 runtime 不改 |
| FR-ING-06 | 支持异步入口：长任务先回执（含 jobId），结果后续推送 | M | 提交长任务后 500ms 内返回 jobId，结果可查询/推送 |

### 4.2 FR-MDL 模型层（适配各种模型）

| ID | 需求 | 优先级 | 验收判据 |
| --- | --- | --- | --- |
| FR-MDL-01 | 通过 OpenAI-compatible Chat API 契约接入模型，模型可按配置选择；M0 有首个受控 provider，M2 验证第二 provider | M | M0 首个 provider 通过契约；M2 同一份 fixture 跑通 ≥2 个 provider adapter，切换无调用方代码改动 |
| FR-MDL-02 | 支持本地模型端点（Ollama / vLLM 类），用于离线与省成本 | M | 断外网情况下本地模型可完成一次问答 |
| FR-MDL-03 | 提供模型降级链：主模型失败按配置顺序自动降级并记录；已开始产生工具副作用的 run 不从头自动重放 | M | 在可重试错误样本中 3s 内启动备选调用；降级事件、成本与最终状态可查；未知副作用状态转人工核对 |
| FR-MDL-04 | 模型能力协商（流式 / 工具 / 视觉 / JSON / 最大上下文），不支持的能力不被编排层强用 | M | `capabilities()` 返回的缺失能力，编排层自动避开而非报错 |
| FR-MDL-05 | Token 与成本计量统一回收，含 reasoning token | M | 每次调用产出 usage 事件，成本可归集到 span |
| FR-MDL-06 | Chat、Embedding、Rerank、视觉、语音、图片与视频能力分别通过 Model/Media 能力契约选择本地端点、企业自建端点或获准在线服务；模型位置与工具执行节点独立 | M | 同一任务可按配置在本地与在线 Chat provider 间切换；Embedding/Rerank 不被错误当作 Chat；视频工具在 Node 执行时仍记录实际模型/服务和数据出域 |
| FR-MDL-07 | 按数据分类、主体、任务和用途执行模型隐私路由：`local_only`、`approved_private`、`approved_cloud`；降级不得扩大数据出域 | M | 冻结样本中标为 local_only 的原文、附件、检索片段和记忆对云端请求数为 0；无合规 provider 时明确阻塞或使用本地能力，不静默降级到云端 |

### 4.3 FR-DEC 快决策层（规则默认，自托管优先）

| ID | 需求 | 优先级 | 验收判据 |
| --- | --- | --- | --- |
| FR-DEC-01 | 决策能力作为独立 Port，提供 ≥3 个 adapter：**rule_fallback（无额外模型依赖，默认且必须可独立运行）/ Kev（自托管）/ Laya（自托管）**；Jev 列为可选托管 adapter，仅在验证网络、授权与数据策略后启用 | M | 三者通过同一份契约测试；仅装 rule_fallback 时不依赖其他决策后端且 `uv run agentos boot` 成功；已安装并验证的后端切换只改配置项，模型效果另行评测 |

## 6. 质量属性场景

| 场景 | 刺激 | 期望响应 | 度量 |
| --- | --- | --- | --- |
| 组件被弃坑 | 某开源依赖宣布不再维护 | 按替换矩阵切到备选实现，上层零改动 | 切换后 kernel/runtime diff 为空，耗时 <1 个工作日 |
| 依赖出现 CVE | 依赖爆出高危漏洞 | 走升级窗口，升级失败按已验证版本回滚 | 回滚 <5 分钟，业务代码无变更；数据迁移须有独立恢复演练 |
| 模型厂商涨价/限流 | 主 provider 不可用 | 在未产生副作用的步骤降级链自动切换并计入成本 | 可重试故障注入下 3s 内开始备选调用，未知副作用转待核对 |
| 远程执行越权 | 注入内容试图触发写操作 | 工具集收缩+审批拦截 | 注入测试集通过率 100% |
| 节点断网 | 长任务执行中网络中断 | 本地续跑、恢复补传、jobId 不变；外部效果未知不盲重试 | 已持久化的本地结果补传成功；未知状态留待对账，不误报完成 |
| 成本失控 | 某流程异常放大调用量 | 预算熔断并告警到手机 | 触发即熔断，告警 ≤60s 到达 |
| 知识库答错 | 知识型问答无授权出处 | 拒绝给出事实结论并返回零命中 | `requireRefs` 的知识问答引用率 100%，越权引用为 0 |
| 企业越权读取 | A 组织用户检索 B 组织记忆、知识或业务记录 | 服务端按资源范围拒绝，记录审计 | 跨域 fixture 中返回/写入条目数为 0 |

## 9. 验收标准

**验收口径**：每项指标在其 §10 首次验收阶段执行；M0 先建立合成测试数据、测试设备与命令记录。涉及外部系统的“成功”以可验证回执为准，超时/断连只表示结果未知。下表门槛是设计目标，实际测试证据未产生前状态为“未验收”。调整门槛须改本文件与 ADR，不可事后修改测试集迎合结果。

| 指标 | 首次验收 | 目标值与样本 | 测量方式 |
| --- | --- | --- | --- |
| M0 写操作安全门 | M0 | 未认证、越权、需要审批但无有效批准的外部写入 0 次成功；所有拒绝与批准有事件 | 用至少 10 个正反例执行授权/审批/审计集成测试 |
| run 恢复与步骤幂等 | M0 | 同 step 重试无重复已确认效果；不同 step 相同参数独立执行；结果未知时 100% 转 `uncertain` | kill/restart、故障注入、账本与业务数据对照 |
| 需求到成果闭环 | M1 | 10 个冻结需求样本（视频制作 4、研究/文档 3、开发/自动化 3）完成目标→计划→Agent→节点→成果；覆盖显式运行环境约束、跨机产物和必要审批，至少一条工具路径经 Hub | 手机、桌面网页、CLI 入口核对任务树/节点/产物/成本；包含两个真实授权节点的一条链路，mock 不算跨机验收；生成器缺失时明确未验证 |
| 复用优先 | M1 | 每个已引入组件可在 §12.3 与依赖台账溯源；重要自研与平台引入取舍有 ADR，未启用的候选组件不要求安装 | 组件清单与依赖台账逐条核对，自研项查 ADR 编号 |

## 12. 需求来源与证据

### 12.1 设计调研依据

本节保留需求形成时的调研依据，不构成当前供应商能力或实现保证。资料核对日期见历史记录，实际集成前按锁定版本复核。

- MCP 协议持续演进，新旧服务端的发现路径与任务能力不同；Tasks 是协商后使用的可选扩展 → 派生 FR-TOOL-09/10、FR-TOOL-07、NFR-SEC。设计依据见 [架构决策](03-架构决策.md)。
- Laya 提供与 Jev 相近的请求路径，但线协议相似不证明决策质量一致；版本、题型、中文样本与校准要分别验证 → 派生 FR-DEC-01/02/07，详见 [架构决策](03-架构决策.md)。
- Kev 明确指 `jaredpalmer/kev`，提供 `/v1/systemone` 接口；与 Laya、Jev 分别验证题型、概率语义、中文质量与成本，不用跨数据集分数替代本项目评测 → 派生 FR-DEC-01/08，详见 [架构决策](03-架构决策.md)。
- 托管服务的网络、账号和数据策略按部署环境核验；Jev 不得作为任何阶段的唯一可用后端，离线时规则可用 → 派生 FR-DEC-08。
- Agent Skills 已成跨客户端开放标准，但各客户端存在私有扩展字段差异 → 派生 FR-SKL-02「只用核心字段」。
- GenAI 语义约定仍在演进且部分字段重命名/新增（含推理 token 计量） → 派生 FR-MDL-05、FR-OBS-01/02。
- 可安装 PWA 的手机访问需要可信 HTTPS；设备本机 localhost 只用于开发 → 派生 FR-EDG-01、NFR-SEC，详见 [架构决策](03-架构决策.md)。
- SQLite 的扩展、分词与中文召回能力须在目标 Python 构建验证；历史其他驱动探针不作为本实现验收 → 派生 FR-KNW-01 的中文分词与双字词样本约束，详见 [架构决策](03-架构决策.md)。
- Octop 已提供自托管个人 AI 助手、Web/CLI/IM、MCP/ACP 与多 Agent 协作能力，但远程桌面和 Agent 委派不等于基于能力与资源的节点调度；将其作为入口或专家 Agent 候选，而非复制其产品层 → 派生 FR-APP-04，详见 [架构决策](03-架构决策.md)。
- WeKnora 已覆盖自托管 RAG、混合检索、引用、API/MCP、RBAC 以及 Compose/Helm 部署；将其作为首个外部 Knowledge Adapter，内置轻量 RAG 保留为个人默认与契约基准 → 派生 FR-KNW-08，详见 [架构决策](03-架构决策.md)。
- Windmill、Temporal 和 n8n 的定位与许可不同。外部引擎须经 Workflow Port 接入并选定唯一 checkpoint/retry 所有者；n8n 的 Sustainable Use License 不按普通 OSI 开源依赖表述 → 派生 FR-WFL-04/05，详见 [架构决策](03-架构决策.md)。
- LiteLLM 可统一多供应商路由与预算，Ollama/vLLM 可提供本地模型服务；接口统一不代表能力、隐私或质量等价，且 LiteLLM 无数据库时不能依赖其预算功能 → 派生 FR-MDL-06/07，详见 [架构决策](03-架构决策.md)。

## 13. 需求变更流程

1. 所有变更先在本文档修改；**改变旧要求语义方向**时新增 ID，旧 ID 标记 `退役` 并注明替代者。只增补测量口径、约束或例外时，可保留 ID，但必须在变更记录写明澄清点。
2. 更新受影响 RTM 行与验收指标。
3. 只同步受影响的架构与工程设计章节；重要取舍在《架构决策》追加或更新 ADR（含退出成本），普通文案与链接整理不新增 ADR。
4. 以 ReAct 方式复评：需求 → 设计 → 实现 三层各自打分，任一未达标回滚到上一层重做。
5. 每轮输出均需附：本轮改动清单、仍存在的缺口、下一轮计划（禁止声称“已完美”）。

## 16. 容量与企业迁移验收

| 配置 | 初始验证负载（设计目标，待实测） | 证明什么 |
| --- | --- | --- |
| personal | 1 个 owner；4 个活动 run；每 run 最多 2 个工具，全局最多 4 个工具；队列上限 200；2 vCPU/4 GiB，不含可选推理 worker | 本人可长期使用，超额任务明确排队或拒绝；数据可恢复、成本可控 |
| enterprise-demo | 100 个合成账号、两角色；20 个活动 run；全局最多 20 个工具；队列上限 1000；4 vCPU/8 GiB，不含推理与外接系统 | 单组织企业适配的权限、调度与数据迁移证据；不能据此声称任意 100 人负载已生产验证 |

M1 先记录 20 次 run 基线，M2 用 ≥200 个任务、30 分钟稳定负载测容量/背压，超载用 2 倍目标输入速率；分别报告成功率、拒绝率、队列等待与执行时间，不能把拒绝算成功。冷启动/热启动、模型、硬件、网络与输入长度随报告冻结。队列等待不计入模型首字但计入用户端到端时间。非流式入口 500ms 内回执是本地网关受理目标，外网往返单列。检索在 10,000 块、既定维度和 ACL 分布上验收，性能改动不得降低权限或召回门槛。

低成本迁移按 **复用不变项、需要修改项、工作量与费用** 报告：不变项是业务流程、技能、领域契约与 fixture；变化项是身份源、策略、数据库/文件存储、外部系统字段映射及部署。M2 记录基线，M5 给实际改动与人时；未演练前只称“有迁移设计”。企业优先一组织一部署，租户字段保留隔离边界，不建设跨客户 SaaS 运营平台。横向扩展先拆 worker，再按持续锁等待/容量瓶颈迁移数据库；企业人数本身不是迁移触发器。
