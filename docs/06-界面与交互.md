# AgentOS 界面与交互

> 版本：2.0
> 更新日期：2026-10-01
> 文档性质：产品交互规范
> 适用范围：目标输入、任务工作区、能力中心与只读访问
> 阅读入口：[文档目录](README.md)

## 1. 产品目标

用户以一个目标开始，在同一个任务空间补充材料、观察进展、处理关键确认、检查成果和提出修改。任务刷新后可继续，长期运行不依赖页面保持打开。

界面采用已接受的 [设计参照](ui-reference/README.md)。参照包含合成任务与本地交互，不构成运行证据；当前实现程度见 [开发计划](04-开发计划.md#2-当前实现)。

## 2. 信息架构

| 入口 | 责任 |
| --- | --- |
| 新任务 | 自然语言目标、资料、自动执行方式；提供可理解的示例 |
| 任务空间 | 全部任务、需要本人处理的过滤、历史续接、失败/阻塞状态 |
| 成果库 | 按来源任务保存报告和媒体，预览、下载、引用与不可变版本 |
| 能力中心 | MCP 工具、Skills、知识后端、执行设备；来源、版本、健康、范围与启停 |
| 最近任务 | 侧栏直接续接，不为每个后台状态建立独立一级菜单 |
| 偏好设置 | 展示与会话偏好；服务端权限/预算另有明确责任 |
| 通知 | 找到需要确认、补充材料、处理失败或核对结果的任务 |

审批呈现在对应任务的对话中，并汇总到通知与任务过滤。用户可看到准备执行的动作、关键参数、设备、影响、原因和确认范围。确认绑定服务端保存的具体调用，参数改变必须重新裁定。

## 3. 视觉与工作区

- 中性浅色/深色随外观适配，石墨色主要操作，蓝紫色强调当前选择与协作状态。
- 导航安静且稳定；新任务页围绕输入，不放全局技术指标墙。
- 对话页由目标、文字、工具事件、角色交接、确认卡和最终成果构成。提示词与原始参数进入步骤详情。
- 电脑上对话与成果/步骤检查器并排；手机上按需打开详情。窄屏保持一个主要阅读路径。
- 对话、执行图、成果是同一任务的视图，不创建互不关联的聊天和运行记录。
- 用短任务标题，完整目标留在用户消息中。真实模型、费用、用量和等待原因按记录显示；未知显示未记录。

默认对话优先；复杂任务可切换协作视图。设计样板允许比较这两种进入方式及成果侧栏，正式产品不把演示开关当成执行策略。

设计参考：[Claude Artifacts](https://support.anthropic.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them) 的对话旁成果窗口，以及 [LangChain Agent Inbox](https://www.langchain.com/blog/introducing-ambient-agents) 的人工介入入口。采纳其交互分工，AgentOS 的角色/设备交接、治理与不可变成果仍按本项目契约实现。

### 3.1 响应式与状态验收

| 项目 | 要求 |
| --- | --- |
| 宽度基线 | 1440、1024、390、360 px；截图记录实际宽高 |
| 参考尺寸 | 1440×900、1024×768、390×844、360×800 |
| 电脑 | 导航、对话和成果层次清晰，宽屏并排查看 |
| 手机 | 单列阅读，导航和成果可展开，提交、审批、下载可达 |
| 可访问性 | 表单标签、键盘焦点和操作名称明确，主要触摸热区至少 44×44 px |
| 内容压力 | 长中文、横屏、200% 缩放与软键盘下不出现页面级横向溢出 |
| 状态 | 加载、空态、成功、失败、等待与权限失效都有明确反馈 |

物理手机须通过受信 HTTPS 验证，不以电脑窄屏替代。PWA 安装、推送和离线业务不因存在静态外壳缓存而视为完成。

## 4. 简单任务

样例：读取一份合成项目记录，整理有引用的周报。

路径：目标 → 读取已授权材料/必要 Skill → 单执行角色处理 → 结构/引用检查 → 交付报告。

UI 展示连续文字、少量可展开工具记录和报告预览。执行图为简洁直线，不为视觉效果拆出多个 Agent。

“自动”执行方式由服务端实际路由决定，明确用户约束进入任务输入。前端不得用样板关键词或模拟状态替代真实执行。

## 5. 复杂任务

样例：结合品牌知识生成活动方案与视觉素材，评审指出来源不足后返修。

参与角色：协调、研究、设计、评审；执行位置：核心可达的授权能力节点。Agent 角色与设备是独立维度，一设备可承担不同角色，一个角色可调用不同设备的能力。

路径：

1. 协调角色保存经过校验的计划 v1、验收条件和输入引用。
2. 研究角色读取授权品牌资料，设计角色在依赖满足后调用已授权的生成能力。
3. 汇总两路成果交给评审。评审以来源、结构和约束检查为依据；若另行启用模型内容评审，应单独记录。
4. 评审发现日期引用不足，给出返修原因与受影响步骤。
5. 形成修订计划 v2，仅补充研究与文案；已确认生成的视觉成果继续复用。
6. 再评审后交付方案新版本与原视觉版本，保留未决项、来源和修改关系。

执行图应区分当前计划依赖与历史交接、返修事件。**当前计划仍为合法 DAG，历史轨迹可以显示返回；不能把循环箭头直接保存为非法 DAG。** 返修固定步骤/尝试和计划版本，受最大轮次、预算及重复动作检测约束。

每次交接显示角色、输入/输出引用、执行设备和当前状态。失败不能标整体完成；缺角色/能力/资料时解释阻塞原因。模型内部推理不出现在视图。

## 6. 流式体验与恢复

流式体验包含两层：可展示的模型输出增量，以及持久化步骤/角色/工具/成果事件。转圈、假百分比和逐字动画不能替代真实执行进展。

建议交互契约：

| 事件 | UI 行为 | 持久性要求 |
| --- | --- | --- |
| 输出开始/增量/结束 | 向当前消息追加可展示正文，结束后保存完整消息 | 增量可短暂；完整正文及关联调用必须可恢复 |
| 计划保存/修订 | 更新当前计划及变更说明 | 固定版本与影响范围 |
| 角色交接/步骤状态 | 更新对应记录与执行图 | 有顺序游标、角色/步骤/尝试 ID |
| 确认请求/裁定 | 在动作附近显示卡片并防重复提交 | 绑定调用与参数，服务端裁定 |
| 成果登记/回传失败 | 出现预览或单独补传动作 | 绑定 subject/run/version/hash |
| 完成/失败/待核对 | 明确状态与下一操作 | 终态必须由服务端决定 |

传输可用受鉴权的流式 fetch/SSE，遵循已有同源和会话策略；具体传输以网关实际接口裁定。当前正文流与执行事件分别持久化，真实验证见 U6 验证记录。

同一事件只能应用一次。刷新/断网重连从游标补拉原任务与完整消息，不重新提交目标。历史恢复先获取快照，再应用增量；输入草稿、已展开详情与阅读位置不因事件更新被清除。阅读旧内容时提示“新进展”，由用户选择回到底部。

区分暂停示例回放、用户请求取消和服务端已确认停止。结果未知先核对；已生成而回传失败只补传，不能重做生成。失败可恢复动作必须由后端按实际能力提供。

## 7. 能力中心与可插拔证明

四个分类保持边界：MCP 是互操作入口，Skill 是任务做法和资源，知识后端通过 KnowledgePort 提供统一语义，执行设备提供被授权的计算/工具能力。

WeKnora 的工具发现证明协议接入；同样本在内置/WeKnora 上执行、引用回查、权限/删除/错误一致性及切回证明后端替换。二者分别验收。

连接流程：配置 → 验证 → 能力发现 → 收窄授权 → 启用。显示配置声明、探针结果和实际调用证据的区别。凭据仅保存于服务端；列表和截图隐藏真实端点、路径与秘密。

知识切换只影响新任务；已有任务固定后端、来源版本、Skill 版本和引用归属。在途任务不静默迁移，外部不可用不自动把同一个引用转到另一个库。尚不支持的摄取/删除/取消能力应明确标注。

## 8. 访问角色与资源发布

管理员/游客是访问角色；协调/研究/设计/评审是执行角色。**游客是默认角色**：无凭据时点「以游客身份进入演示空间」即换取只读会话，不要求访问码（见 [工程设计 §7](02-工程设计.md#7-访问授权与演示发布)）；兑换码仅作可选定向邀请。管理员仍走密码/令牌登录。游客不能创建任务或控制执行，只读指定演示任务的脱敏链路与明确发布的资源版本。完整授权约束见 [工程设计](02-工程设计.md#7-访问授权与演示发布)，UI 不裁定权限。

管理员沿用新任务/任务空间/成果库/能力中心/偏好设置导航 + 顶栏通知，**不再有一级“待审批”**；「演示访问」页提供默认演示通道开关、逐任务/逐版本/逐动作勾选、游客可见预览、发布 revision 与免登访客访问记录。新版本默认不自动公开给已在访会话，发布新 revision 才扩大范围。

游客沿用同一工作区视觉，侧栏为“演示任务、演示成果、访问说明”，顶栏“演示空间 · 只读访问”；首页没有输入框或新任务按钮。详情仍有对话/执行图/成果，可查看已发布计划、交接、工具摘要、审批裁定历史和来源片段，无审批/修改/重试/Hub 管理控件；窄屏下成果与发布范围通过展开按钮可达。不可读引用不能跳转整份私有资料，未开放下载不显示可点击下载动作；未发布成果不显示预览。到期、被撤销或管理员暂停时清页面与 Blob，显示访问已结束。事件呈现为可读状态/交接，不出现原始事件名或 JSON；原始 JSON 只进管理员高级详情。
