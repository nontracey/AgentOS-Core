## 1. 已确认的方案

**AgentOS 定位为可自托管的 AI 集成与治理底座。企业已有模型、Agent、知识库、身份系统、工作流和项目系统，通过适配器接入，形成统一任务、权限、审批、成果与成本视图。**

首版选择：**Codex 执行 + Temporal 编排 + React Flow 节点编辑 + Authlib 企业登录 + WeKnora 知识接入 + 官方 MCP SDK 双向互通 + Agent Skills**。模型复用企业网关；没有网关时提供 LiteLLM 开源 Proxy 配置。OpenTelemetry 负责标准观测。

本仓库为个人开源项目，上述开源件作为默认实现。落地公司时优先使用其既有框架与系统，通过同一契约替换默认实现，不强制另起一套身份、项目或模型平台。

| 本次确认后做完整闭环 | 本次只留契约与合成适配示例 | 后续按真实需求实施 |
| --- | --- | --- |
| Codex、上下文压缩、受限沙箱、自定义节点与可视化工作流、OIDC/JWT、WeKnora、MCP 双向、Skill、基本预算、执行追踪 | IM 入口、外部项目关联、企业额度来源、其他 Agent 协议/工作流引擎适配 | 真实 IM 渠道、企业额度分配、旧项目系统同步、复杂审批组织、SAML/LDAP 代理接入、A2A |

企业额度和项目管理后置；当前 run 预算与跨主体权限是接入安全所需，随首版完成。企业真实系统、凭据、手机设备尚未提供时，分别标为未验，不用合成服务代替验收。

核心与可选能力按功能连接，部署位置不固定。当前最小核心/发现/节点/自主选择的实现差距与后续方案见 [能力接入模块](modules/capabilities.md)。组件接通不等于完整的即接即用。

## 2. 改造前代码审查（历史基线）

本节记录确认前读取的实现、对应需求与 [原开源替换评估](07-开源替换评估.md)，当时没有读取部署私密配置。以下问题已经由 REBASE-01 按当前范围改造；不能把本表当成当前缺陷清单。最新状态见 [开发计划 §3.1](04-开发计划.md#2-当前实现)，结果见 [验证说明](validation.md)。

| 发现 | 代码落点 | 对改造的影响 |
| --- | --- | --- |
| 主路径硬装配本地身份；OIDC 只在测试装配 | `apps/composition.py`、`services/identity.py` | 企业登录必须进入真正组合根，不能以适配器单测代替 |
| OIDC 写死 certs 路径、角色格式与默认租户；subject 优先用户名；身份有效期未夹紧到 JWT 的 exp | `adapters/identity/oidc.py` | 使用 discovery、可信通道配置、稳定主体映射；有效期不能超出原票据 |
| worker 领取、执行、租约和部分恢复使用固定 `default` 租户 | `runtime/worker.py`、`runtime/loop.py` | 只改身份层不够，执行链必须全程使用真实租户与主体 |
| 通用循环没有上下文压缩；计划子任务也有独立循环 | `runtime/loop.py`、`services/planning.py` | 引入 Runtime Port，统一委托 Codex，不再维护多个推理循环 |
| 网页报告和协作由独立 runner 接管；报告直接调 ModelPort | `services/template_runner.py`、`services/collaboration.py` | 必须把真实网页主线纳入迁移，不能只替换通用 loop |
| 工作流主要是发布 TaskPlan、注入内部 run；传入 inputs 只用于 hash，没有放入执行 payload | `services/workflow.py` | 建立真实输入输出绑定、节点类型、条件分支、审批等待与引擎运行映射 |
| WeKnora 声明关键能力为 false，探针关闭启用；不是已完成的真实集成 | `adapters/knowledge/weknora.py` | 依据锁定版本 API 重做适配并真验；不能仅开探针 |
| 已有 MCP 是调用外部服务的 Hub；`/v1/mcp/servers` 是管理 API | `adapters/tools/mcp_hub.py`、`apps/gateway.py` | 补真正的入站 MCP Server，让外部 Agent 可受控使用底座 |
| 隐私扫描跳过全部测试，仅覆盖部分文件类型，并输出命中原文片段；测试说明仍有需脱敏的内网地址 | `services/oss_check.py`、`tests/contract/test_knowledge_weknora_live.py` | 提交前覆盖 diff、新文件、测试和公开生成物；报告只给位置与规则，不能再次泄露 |

已有 FastAPI、官方 MCP SDK、PyJWT、SQLite、资源授权、审批指纹和副作用账本可复用。问题集中在基础能力重复实现、接入不完整和运行边界尚未统一。

## 3. 对原评估的独立裁定

| 原评估建议或论据 | 本轮裁定 |
| --- | --- |
| Codex 替代自研 ReAct 循环 | 同意，但迁移全部实际执行路径，并先验治理闸门。Codex 是默认运行时，底座保留替换入口 |
| 任意兼容端点都能用、压缩缺口自动消除 | 需限缩。核对的 Codex 配置协议是 Responses；原有 Chat Completions 端点不能直接视作等价。压缩和推理状态保留取决于模型/服务能力 |
| 保留推理链与压缩能带来数倍提升，且只有 Codex 满足条件 | 原文没有可复核的固定模型、样本和基准链接，不能作为定量结论或排他结论。本项目需同模型对照验收 |
| Run 对应 thread，一次模型调用对应 turn | 需重划：一个工作流 run 可含多个 agent 节点，每个节点有 thread；一个 turn 内可发生多次推理和工具调用 |
| Codex 动态工具承载治理 | 动态工具仍是实验 API。首版实测采用锁定 0.159.2 dynamicTools 双向 RPC 进入既有 executor；MCP 双向接口另用官方 SDK，不 fork Codex |
| `planning.py` 和 `workflow.py` 全部交给 Temporal | 同意迁移调度、等待、恢复和重试；保留薄的节点定义与适配。Temporal 不自带本项目所需的可视化节点编辑器 |
| LiteLLM 先 SDK，避免新进程 | 仅适用于仍由 Python 直接发出的请求。Codex 内部请求须经过企业网关或 LiteLLM Proxy，才能在调用前实施预算和隐私路由 |
| 先 OTel、定时、数据库，再工作流，最后执行循环 | 不采纳此顺序。先完成身份/租户与 Codex 治理闭环，再工作流与知识互通；OTel 随链路补，数据库整体替换后置 |
| 100 行以内一律不换，kernel 全部保留 | 不采纳绝对规则。依据风险、语义与总维护成本判断；密码学、协议和沙箱不会因为代码少就值得自研。kernel 保留必要契约和治理语义，重复执行机制可删除 |
| ID4 只需 OIDC，JWT 配置化即可 | 方向正确，但需区分网页登录、API access token 和无 discovery 的 JWT。ID4 的已有部署可以适配，不作为新部署依赖 |
| 内置 RAG 和对象存储保持/替换 | WeKnora 为集成配置默认知识后端；内置轻量库降为可选个人/测试实现。暂无必要同时迁移资产到对象存储 |

Codex 的压缩可以保留供后续推理使用的状态，这不等于公开完整推理链。官方说明压缩状态可能为不透明的加密内容；第三方接口的同等能力需独立验证。[官方压缩说明](https://developers.openai.com/api/docs/guides/compaction)

## 4. 选型、理由与退出路径

| 能力 | 默认项目 | 选择理由与边界 | 替换/退出 |
| --- | --- | --- | --- |
| Agent 执行 | [openai/codex](https://github.com/openai/codex)；Apache-2.0 | app-server 可集成；框架提供执行循环、会话、压缩与沙箱。官方 Python SDK 已存在，但其公开高层接口不足以证明全部审批回调可用，先验证，再决定 SDK 加薄 RPC | Runtime Port 隔离 thread/turn/item；外部 Agent 或另一运行时可替换 |
| 持久工作流 | [Temporal](https://github.com/temporalio/temporal) + [Python SDK](https://github.com/temporalio/sdk-python)；MIT | 为审批长等待、故障恢复和跨系统动作提供成熟编排。新增服务/worker 运维成本明确接受 | Workflow Port；复用企业既有 BPM/Temporal，外部流程以受控节点调用 |
| 可视节点编辑 | [React Flow / xyflow](https://github.com/xyflow/xyflow)；MIT 核心 | 不自研画布、拖拽和连线；参数表单使用 RJSF 6.11.0/AJV8（Apache-2.0），schema 与治理由本项目定义，属于集成契约 | 仅工作流页面引入 React/Vite 构建入口，产物仍 `/ui/` 同源；不全站迁移 |
| 企业身份 | [Authlib](https://github.com/authlib/authlib)；BSD-3-Clause；保留 PyJWT 验签 | Authlib 处理 OIDC discovery、授权码登录等标准流程；PyJWT 处理受信 JWT/JWKS。保留本地个人身份，不自建 IdP | Identity Port；接企业现有 ID4、Keycloak、受信 JWT 或身份代理 |
| 知识库 | [Tencent/WeKnora](https://github.com/Tencent/WeKnora)；项目主许可 MIT，依赖另核对 | 使用其摄取、检索与引用；接已有服务，或提供可选集成部署。当前上游也有 Agent/Skill/IM，适配已有能力，避免复制其产品 | Knowledge Port；不共享其私有数据库，导出来源/引用映射 |
| 工具与对外服务 | [官方 MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)；MIT | 同一 SDK 实现出站 Client 和入站 Server；复用当前 Hub | 标准协议、能力协商、独立安全代理 |
| 技能 | [Agent Skills](https://github.com/agentskills/agentskills) 开放格式 | 固定来源、版本、digest；投影给运行时，不另造格式 | 可导出技能原文件与版本元数据；具体许可逐技能检查 |
| 模型接入 | 企业网关优先；否则 [LiteLLM](https://github.com/BerriAI/litellm) 开源 Proxy | Codex 与普通模型调用共用网关；支持 Responses 路由。企业目录有独立许可，不能把整仓功能视为 MIT 免费能力 | ModelGateway 配置/适配器；不依赖商业管理 UI |
| 可观测 | [OpenTelemetry Python](https://github.com/open-telemetry/opentelemetry-python)；Apache-2.0 | 标准 trace/usage 元数据关联，正文外发默认关闭 | OTLP 接企业现有观测系统；本地事件视图继续可用 |
| 提交前凭据检查 | [Gitleaks](https://github.com/gitleaks/gitleaks)；MIT | 成熟凭据规则替代仅靠少数正则；本地 hook 与 CI 使用脱敏输出。上游当前进入安全维护期，锁定版本并复审 | 与人工隐私检查互补；不把凭据扫描等同个人信息扫描 |

[Codex 当前配置 schema](https://github.com/openai/codex/blob/ed0cc1a4ab30e1e83f1214e7a368c55b83fd089d/codex-rs/core/config.schema.json) 中 `WireApi` 为 `responses`。LiteLLM 有 [Responses 接口](https://docs.litellm.ai/docs/response_api)，但接口格式转换不证明推理状态、工具配对或压缩等价；实际提供方逐项做契约测试。

替代方案也做了核对：[LangGraph](https://github.com/langchain-ai/langgraph) 适合有状态 Agent 图，但不额外引入第二套 Agent 执行机制；[OpenHands SDK](https://github.com/OpenHands/software-agent-sdk) 是有价值的容器运行时备选，首版先接 Codex；[Windmill](https://github.com/windmill-labs/windmill) 提供现成工作流/UI，但 AGPL 与完整平台部署需单独取舍；[n8n](https://github.com/n8n-io/n8n) 使用 Sustainable Use/Enterprise License，作为企业已有外部引擎接入，暂不内嵌成 Apache-2.0 项目的默认工作流平台。

原 [IdentityServer4](https://github.com/DuendeArchive/IdentityServer4) 已归档且不再维护。此方案支持企业现有服务的标准协议接入；本项目不安装新 ID4，也不要求企业为接入 AgentOS 先换身份体系。

## 5. 系统如何接在一起

系统分层与通用部署统一见 [总体架构](01-总体架构.md)，具体执行调用见 [执行模块](modules/execution.md)。

本节保留已确认的设计边界；当前节点种类、运行限制和未交付项以 [开发计划](04-开发计划.md) 与 [工程设计 §5.4](02-工程设计.md#54-集成工作流与新真实运行时) 为准。

治理不会仅存在于最外层入口：每个节点、每次工具执行、每次模型出域与每次成果读取都复核相应边界。

### 5.1 Codex 接入与沙箱

1. 新增 Runtime Port，表达 start/resume/events/cancel/capabilities。Codex 特有类型只进入 adapter。单 agent 任务直接进入运行时，工作流中的 agent 节点由 Temporal activity 委托运行时。
2. 持久化 `tenant + subject + run + node + runtime + thread + turn` 关联；不得把任意 thread ID 当授权证明。Codex 只拥有会话上下文，Temporal 只拥有工作流历史，AgentOS 只拥有业务状态和治理/副作用账本，不相互复制整套历史。
3. 管理明确的进程和工作空间归属。运行时读取独立受控配置，不继承桌面个人凭据或工作目录中的任意高权限工具；每个工作负载隔离素材、Skill 和输出。
4. 当前锁定 app-server 的 dynamicTools 双向 RPC 进入 `execute_tool_step`，复用权限、预算、审批指纹、稳定幂等键和对账。MCP 双向服务是独立的标准接入层。Codex 原生 shell/文件工具关闭，沙箱为只读；发布和写业务系统只能经受控 executor，不向运行时交付企业原始写凭据。
5. Codex 自带的 OS 沙箱保护文件/命令；企业多主体运行再加成熟容器/VM 隔离、受控挂载和网络出口，不自研沙箱。不将沙箱等同企业权限系统，也不承诺任意命令可做业务幂等。
6. 当前拒绝 app-server 原生审批请求；业务 dynamicTool 调用由服务端 ApprovalService 裁定，参数/工具/主体改变后重新裁定。动态工具为锁定版本的实验接口，升级须复验，不赋予引擎自行批准业务的能力。[app-server 协议](https://learn.chatgpt.com/docs/app-server)、[官方沙箱说明](https://learn.chatgpt.com/docs/sandboxing)
7. 使用框架内置压缩和恢复，不解析、改写或公开不透明推理状态。审计展示工具、参数摘要、结果、来源和可用过程摘要；压缩后重新注入最新权限约束，实际授权仍查服务端。第三方模型只宣称真验通过的压缩能力。

### 5.2 工作流与自定义流转节点

- React Flow 编辑节点与连线；服务端校验后发布不可变版本，运行固定定义和节点实现版本。
- 当前工作流通过网页、受权 HTTP/MCP start 或受控固定版本启动工具接入；独立 Webhook 触发配置、Temporal Schedule 定时入口未实现，按后续需求接入。定时应委托 Temporal，不在新工作流旁继续扩展自研 cron 调度器。
- 当前可编辑节点为 AI、工具、条件、等待、自定义；知识/MCP/HTTP/成果能力经受控工具或注册 Adapter 接入，审批属于工具执行闸门，不是另一个已上线的独立节点。输入输出按 schema 和依赖绑定；计时/分支可并行，单 worker 的工具提交仍串行。
- 自定义节点由受信开发者注册 manifest 和 adapter，声明 schema、能力、风险、超时、重试与对账能力；普通使用者选择、配置和组合。首版不提供任意包安装和不受限脚本执行。
- Temporal 是流程等待、checkpoint 和节点调度重试的唯一所有者；真实图交给 Temporal；旧 TaskPlan/scripted 的兼容调度暂留，不再承载新的真实执行引擎。角色说明、成果校验、审批与领域规则继续复用。
- activity 重新执行时先查逻辑节点/步骤账本。已确认结果复用；外部结果未知暂停对账；仅被证明可安全重试的动作重试。引擎重试次数不得变成新的业务幂等键。
- 审批通过 signal 唤醒，醒来后复验权限与批准有效性。不可逆动作不靠通用“自动补偿”回滚。
- 已有企业流程引擎先以外部流程节点/API 适配接入；需要其直接拥有编排时实现 Workflow Port，并声明该 run 的唯一重试所有者。

### 5.3 OIDC、ID4 与既有 JWT

- 网页 OIDC 登录采用授权码 + PKCE，校验 state/nonce，票据留在服务端受控会话；API 使用目标为 AgentOS 的 access token，不把 ID token 当 API 通行证。[Authlib Starlette 接入](https://docs.authlib.org/en/v1.6.9/client/starlette.html)
- OIDC 通道使用允许列表中的 issuer/discovery/JWKS；无 discovery 的 JWT 通道配置可信密钥/JWKS、issuer、audience、算法与有限时钟容差。opaque token 仅在已配置 introspection 时接受。
- 不依 token 字符形态决定信任；未验签的 issuer 只能选择预配置通道，不能触发任意 URL 访问。验签失败不回落本地管理员。
- 主体使用稳定的 issuer + sub 映射，用户名只显示。组织可以来自经验证声明与服务器维护的映射；请求头或输入不能凭空创建可信租户。无法映射时默认拒绝。
- 更新 IdentityService、AuthSessionService、资源授权、worker、租约、回调和恢复链。权限有效期取外部票据/本地策略较短值；刷新、退出、角色变化和撤权语义分别实现，不把短 TTL 宣称即时撤权。
- 企业不支持即时内省时明确撤权窗口；本地撤权仍用于暂停任务及阻止继续派发。SAML/LDAP 未来由企业既有 broker 转换，不手写 XML/目录认证栈。

### 5.4 WeKnora、MCP、Skill 与扩展

- WeKnora 按固定 API/镜像版本实现 ingest/search/resolve/delete，跟踪来源版本、引用、异步摄取与删除失效；由明确的 workspace/用户/知识库映射限制查询范围，并返回后再次校验。共享全权 API key 不能替代用户授权。
- 不能保证查询前隔离的部署保持禁用；只接检索也不能标成 KnowledgePort 全功能。切回其他后端不改变正在运行任务固定的来源绑定。
- 现有 MCP Hub 继续用官方 SDK；新增 Streamable HTTP 入站 MCP，首批仅暴露提交任务、查状态、受权读取成果、列出允许能力。长任务返回 run 句柄；不对外暴露 shell、数据库或管理员工具。MCP OAuth 与 access token 校验复用成熟库/企业网关，不能裸露无鉴权服务。
- Skill 仅投影已授权、已固定版本的内容到运行时；其工具声明是能力请求，不能自授权限。脚本仍受沙箱和工具代理约束。
- IM、HTTP 和外部 Agent 共用受理契约与幂等规则。IM 账号先绑定企业稳定主体，消息签名/回调验真；不能让群聊身份自动获得群内全部资源。
- 项目系统保留原系统作为事实来源；先定义外部项目引用、受权查询、事件回流和显式写操作接口，不建第二套项目管理。新增适配器声明字段映射、服务身份与委托身份、错误、限流和对账能力。
- 企业额度后续从已有平台同步或经 QuotaPort 查询/预留/结算，按组织、项目、用户配置；跨库预留采用明确对账流程，不假定分布式原子事务。首版已有 run 预算仍必须在真实调用前有效。

### 5.5 模型、成本与部署

- Codex 内部模型请求与压缩请求均通过受控网关；用短期限定凭据绑定主体/任务及允许模型，通过网关调用前钩子检查数据出域、限额和预算预留，结束后结算。只读取 turn 末 usage 无法实现调用前预算闸门。
- 有企业成熟模型网关时直接复用。没有时提供 LiteLLM 开源 Proxy 配置与薄治理钩子，避免另写供应商协议转换器；须真验 Responses 流、工具调用、usage、压缩以及第三方桥接的限制。
- 低预算拒绝发生在派发前；在途误差记录结算差额。正文已输出后不换模型拼接答案；`local_only` 的降级不得扩大出域范围。
- 最小个人配置：FastAPI + SQLite + 受控 Codex 进程，按现有网关能力接模型。完整集成配置增加 Temporal/数据库/worker，按需 LiteLLM 与 WeKnora；均可部署一台宿主机，但不再宣称单进程。
- Temporal 开发服务器仅用于开发/合成联验，完整部署配置使用受支持的持久化服务。WeKnora 可接企业已有实例，无需默认安装全部 AI 平台；原有执行工具及数据不覆盖。
- 本轮不整体重写 SQLite 为 SQLAlchemy，不迁资产到 MinIO，不另建 RAG 或独立权限平台；WeKnora 所需检索器使用其官方支持的 Qdrant。后续扩库时按需求选成熟迁移工具；涉及存量数据先备份、迁移演练并保留回退路径。

## 8. 什么算改到位

代表性演示：企业主体登录 → 受权选择外部项目引用与 WeKnora 材料 → 编辑或选工作流 → Codex 使用固定 Skill/MCP → 外部写入待批 → 审批后产出新版本成果 → 外部 Agent 通过 MCP 查询 → 回查来源、节点、耗时与成本。

| 验收面 | 必须证明 |
| --- | --- |
| 运行时与压缩 | 真实 Codex/模型运行，强制跨压缩窗口继续任务；检查关键信息、工具配对、成果与权限；提供方不支持的能力明确拒绝或降级声明 |
| 沙箱与授权 | 越界文件/网络/秘密访问拒绝；无批准不能写业务系统；Skill/提示注入无法绕过；取消后不能继续派发 |
| 预算 | 低额度调用前拒绝，Codex 多次内部请求与压缩均计量；并发预留与在途差额可解释；估算不写为实测 |
| 身份 | OIDC 登录/刷新/退出，ID4 风格与无 discovery JWT 两种配置；issuer/aud/算法/exp/kid 轮换及映射异常拒绝；真实企业 IdP 另验 |
| 多主体 | 两组织×两角色从提交到 worker、知识、工具、沙箱、成果、回调、恢复都隔离；同名用户跨 issuer 不串号 |
| 工作流 | 自定义节点、输入输出、条件/并行、固定版本、审批 signal、重启、取消；Activity 重试不重复已确认副作用；未知结果停对账 |
| WeKnora | 真实摄取/检索/引用回查/删除、跨主体负向与后端切回；未提供服务时保持未验 |
| MCP 与 Skill | 独立客户端入站 MCP 真互操作；出站服务真调用；版本固定与权限交集；未协商能力不调用 |
| 交互与兼容 | 电脑/手机视口、详情直开、同源构建物、旧 SW 升级、旧任务/成果可读；物理手机独立真验 |
| 工程与公开物 | 适用行为/契约/安全/恢复测试、完整既有发布门禁；新前端实际 build/typecheck；许可证清单、文档阅读版、diff/新文件/生成物脱敏 |

面试叙事可以写为：**“设计并实现一个可自托管的 AI 集成底座，用成熟运行时和工作流承载执行，通过标准协议与适配器连接既有 AI/企业系统，并统一权限、审批、恢复、成果与成本。”** 当前只能陈述已实现并有证据的部分；真实企业生产、收益倍数与规模能力不由设计文档证明。

## 10. 开源优先复核与保留例外

2026-10-01 再次按实际装配、启动校验、运行入口和锁文件复核：**核心真实执行已符合公司既有框架优先、否则成熟开源优先的原则；这不等于零自研，也不等于所有企业生产条件已经验收。** 实际推理入口交给 Codex，工作流交给 Temporal，画布交给 React Flow，企业标准认证交给 Authlib/PyJWT，模型协议桥接交给 LiteLLM，知识接入 WeKnora，MCP 复用官方 SDK。原有 loop/PlanRunner 的确定性实现只服务 scripted 兼容样本，配置禁止用其驱动真实模型。

本次同时核对了 [Codex](https://github.com/openai/codex)、[Temporal SDK](https://github.com/temporalio/sdk-python)、[Authlib](https://github.com/authlib/authlib)、[WeKnora](https://github.com/Tencent/WeKnora)、[LiteLLM](https://github.com/BerriAI/litellm) 和 [Gitleaks](https://github.com/gitleaks/gitleaks) 上游。选型依据是已锁定版本的能力、许可及集成验证，不把开源、流行度或较新版本等同成熟性保证。Codex 动态工具为实验接口；WeKnora 与模型网关升级需复验；Gitleaks 的维护边界已在 §4 声明。未经验证不追随浮动版本。

### 10.1 保留范围、成本与退出路径

| 保留实现 | 比较与保留理由 | 维护、兼容和许可边界 | 替换/退出条件 |
| --- | --- | --- | --- |

| 本地个人登录、短时令牌封装和会话撤权 | 保留单人离线启动与旧会话兼容；与企业 Authlib/PyJWT 通道分离。PBKDF2/HMAC 使用标准库，但令牌格式和轮换政策仍是自研例外。完整 IdP 的部署与用户体系迁移超出当前个人闭环 | 承担密码、过期、刷新、撤权安全回归；不能称它为成熟企业身份服务。现有企业接入使用标准 OIDC/JWT，不扩建自研 IdP | 多人本地账号或企业认证需求进入范围时，先评估既有 IdP/成熟账户组件；优先迁往标准认证，旧令牌明确退役 |
