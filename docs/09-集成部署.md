# AgentOS 集成部署与接入

> 版本：2.1
> 更新日期：2026-10-01
> 文档性质：核心启动与按需能力接入
> 适用范围：单核心实例，可连接同机或远程已有服务
> 阅读入口：[文档目录](README.md)

## 1. 从一个核心开始

先运行一个 AgentOS 核心，默认提供同源工作台、HTTP API、入站 MCP、任务/成果及权限/审批/预算。用户不必部署 WeKnora、LiteLLM、Temporal 或额外执行机器才能打开工作台。真实自主任务需要受控 Codex 程序和已验证模型端点。

能力接入由功能需求决定；服务可在同机、其他机器、企业已有平台或云端。地址与凭据可配置，设备型号、操作系统和机器数量不是拓扑要求。当前是单核心，分布式核心副本和 HA 未验。产品关系见 [总体架构](01-总体架构.md)。

| 需要什么 | 配置/注册什么 | 不接入时 |
| --- | --- | --- |
| 真实自主任务 | Codex 程序、模型端点/路由、凭据、预算与出域策略 | 默认 scripted 仅用于验证，不是假装真实 AI |
| 固定持久工作流 | Temporal address/namespace/queue | 普通任务可用；图工作流不可运行 |
| 外部知识库 | WeKnora URL/版本/KB/凭据，或后续 Knowledge Adapter | 默认内置；可配置 disabled 彻底关闭知识能力 |
| MCP 工具 | 能力中心注册 HTTP/stdio 服务，按需探测 | 无外部工具；注册自动发现，目录读取按 60 秒 TTL 刷新，探针可立即刷新 |
| Skill/执行节点 | 安装固定版本 Skill，配对授权节点 | 使用现有核心能力，不要求额外机器 |
| 企业登录 | 可信 OIDC/ID4/JWKS JWT 或独立 HS256 通道 | 使用本地身份 |
| 其他 Agent | `/mcp/` + 平台认可的 Bearer 与权限 | 默认 UI/HTTP 入口继续可用 |

已支持知识 disabled、统一工具目录/发现状态和节点 schema 表单；工作流/外部 Agent 工具化与接入管理 MCP 仍待实施，详见 [能力接入模块](modules/capabilities.md)。

## 3. 控制面启动

```sh
uv sync --frozen
cd frontend/workflow
npm ci
npm run typecheck
npm run build
cd ../..
uv run uvicorn --factory agentos.apps.gateway:create_app --host 127.0.0.1 --port 8800
```

打开 `http://127.0.0.1:8800/ui/`。工作台默认提供；React Flow 生产文件由上述 build 生成并由同一核心 `/ui/` 提供，没有第二套后端。首次本地管理员密码位于数据目录 `owner_password.once`，不打印或提交。

无配置是 scripted 验证环境。真实 AI 最小配置使用 [core.example.toml](../deploy/core.example.toml)，复制为受保护数据目录中的 `agentos.toml`，通过 `AGENTOS_DATA_DIR` 选择。设置自己的模型端点/名称，`runtime_gateway_url` 匹配核心监听地址，凭据由 `AGENTOS_MODEL_API_KEY` 注入。真实模型必须选择 Codex，不能重新启用自研真实推理循环。

增加企业身份和工作流可参照 [integration.example.toml](../deploy/integration.example.toml)。本地个人启动脚本不是可移植部署契约；公开用户使用 Settings/TOML/环境变量及标准入口。不要照搬个人配置文件或硬编码的模型别名。

## 4. 按需连接模型与组件

企业既有网关优先。可兼容且通过工具/压缩/恢复验证的端点可直接配置；没有网关时提供 [Compose 配方](../deploy/components/compose.yaml) 与 [LiteLLM 示例](../deploy/components/litellm.yaml)。Compose 是可选服务配方，不是启动核心的前置条件，可按服务名选择，不要无差别安装全部组件。

安装前检查是否已有可复用服务、版本、架构、空间、网络与备份。不要打印 Docker Env、私有挂载、日志或配置全文，不自动删除/替换已有卷。秘密存本地 `private.env` 或企业秘密系统，不进入模型、浏览器或流程定义。

模型位置与数据出域分别配置。`model_egress=local` 只允许适合本地边界的数据路径；云端必须显式选择并经平台策略裁定。OpenAI 兼容的 Chat Completions 不保证 Codex 的 Responses/工具/压缩语义兼容，换端点先验证。协议桥接复用 LiteLLM，平台不另写转换层。

LiteLLM 配方中的模型名字只是示例别名，用户可映射为自己的模型。已有权重不必为了 AgentOS 重新下载。严格模板的消息排序与空工具压缩请求，按已验证的 LiteLLM 路由配置处理，不对所有模型一概承诺。

### 4.1 上下文压缩与限流恢复

压缩由 Codex 管理，配置的模型提供摘要推理；平台等待压缩完成，再继续原线程。所有推理与压缩经过预算/出域闸门，执行记录留在平台账本，不公开模型隐藏推理链。

不同提供方对空工具、tool_choice 和压缩请求的兼容性可能不同，按目标端点验证网关路由；不要把某个实例的参数修正作为通用配置。结构化 429 会暂停原任务，恢复仍须核权和效果对账；不自动更换 key、模型或重放已确认效果。

### 4.2 Temporal

可以连接已有 Temporal；本地开发可用官方 CLI 的 `server start-dev --db-filename ...` 保存状态。配方中的开发服务不代表生产高可用。容器包装见 [Dockerfile](../deploy/components/Dockerfile.temporal)，镜像按目标架构验证，address/namespace/queue 可替换。只启动与自己功能相关的服务，不按机器类型绑定组件。启动连接失败在 5 秒内隔离，普通任务和 UI 继续可用；恢复后重启核心重新连接，不自动迁移既有工作流。

## 5. 外部知识接入

不使用知识库时设置 `AGENTOS_KNOWLEDGE_BACKEND=disabled`，或 TOML 顶层 `knowledge_backend="disabled"`。核心不装配知识后端、不会给新任务绑定知识，模型与入站 MCP 不提供检索工具，UI 显示未启用；HTTP 知识操作返回 unsupported，已有数据不删除。需要时改为 builtin 或 weknora 并重启。

首个 Adapter 为 WeKnora v0.8.2：配置 `AGENTOS_KNOWLEDGE_BACKEND=weknora`、`AGENTOS_WEKNORA_URL`、`AGENTOS_WEKNORA_VERSION`、`AGENTOS_WEKNORA_KB_ID`、`AGENTOS_WEKNORA_TOKEN`。内容票据只授权指定 KB；版本探针票据由 `AGENTOS_WEKNORA_PROBE_TOKEN` 提供。模型与 embedding 指向自己的已有端点，不固定操作系统。

[SQLite/Qdrant 覆盖示例](../deploy/components/weknora-qdrant.override.yaml) 是一种已验证配方。用户应使用与现有数据、CPU 架构和检索要求相容的官方部署；不把检索驱动切换视为自动数据迁移。旧数据先备份，必要时官方接口重建索引。

摄取先登记 pending，派发后保存远端回执；超时只对账已有请求，不重复上传。删除先本地撤权。切换后端只影响新任务，旧运行与来源仍固定原后端/版本。完整治理关系见 [执行模块](modules/execution.md)。

## 6. 企业身份与 Agent 互通

企业既有身份优先。OIDC/ID4 配置可信 issuer、audience、client、scope、组织/角色映射；Authlib 执行授权码/PKCE/state/nonce。没有 discovery 的 JWT 用固定受信 JWKS，旧 HS256 项目使用独立通道，算法不混用。subject 来自 issuer+sub，客户端不能自报组织/角色。上游票据只存加密 vault，浏览器用 HttpOnly cookie；生产 HTTPS。

当前网页登录到期需重登，长任务授权不会自动续期。真实 IdP、组织规则与企业长任务委托仍需实际接入验证。

其他 Agent 可以通过官方 Streamable HTTP MCP 连接 `/mcp/`，使用合适 audience/权限的 Bearer。目前提供 task_submit/status/cancel、knowledge_search、skills_list，仍走同一受理和权限。帮助用户发现、探测和注册能力的管理工具尚未暴露；不能把“已有入站 MCP”当成“Agent 已能完成全部接入配置”。

MCP 服务接入后工具可出现在工作流工具选择中，Skill 需安装固定版本，自定义节点需服务端 Adapter。工具参数表单与目录同步已实现；已发布流程/外部 Agent 的自主选择等后续边界见 [能力接入方案](modules/capabilities.md#2-统一工具目录与治理)。

## 7. 隐私、验证与退出

公开配置只使用占位符，身份、地址、凭据与实际挂载留本地。配置 Gitleaks 8.30.1 后运行 `uv run python scripts/check_privacy.py`，人工核对 diff 与生成物；`git config core.hooksPath .githooks` 可启用提交 hook。公开检查与验证边界见 [验证说明](validation.md)。

停机保留业务账本、资产、身份/vault、撤权与运行时恢复状态；先在隔离目录验证备份恢复，再切换。退出组件前核对固定运行与来源，不改绑旧引用或删除旧卷。原始历史与现场日志仅本地留存，公开仓库保留当前设计、契约和必要验证摘要。
