## 1. 阅读路径

- 使用项目：[README](../README.md) → [集成部署](09-集成部署.md) → [部署与运维](05-部署与运维.md)。
- 看系统：[总体架构](01-总体架构.md) 先看分层与通用部署，再按需读 [执行模块](modules/execution.md) / [能力接入模块](modules/capabilities.md)。
- 看实现：[工程设计](02-工程设计.md) → [架构决策](03-架构决策.md) → 对应代码与契约。
- 继续开发：[开发计划](04-开发计划.md) → [当前交接](dev-notes.md) → 按 ID 查询 [需求规格](00-需求规格.md)。
- 复现检查：[验证说明](validation.md)；不依赖本地日志、截图或历史记录。

## 3. 维护约定

Markdown 是唯一维护源。00/01/02 HTML 使用 `scripts/md2html.py` 重建；架构图使用官方 Mermaid CLI 生成，见 [图维护](diagrams/README.md)。总图只承担系统分层，模块细节放模块文档，不把个人设备拓扑当通用产品设计。

状态与待办只写开发计划，dev-notes 只保留当前交接。保留必要 ADR、来源和许可；不公开整个开发过程目录。本地 `docs/history` / `evidence` 被忽略，公开链接和 CI 不能依赖它们；需求编号校验使用独立公开基线，不读取旧归档。

[UI 设计参照](ui-reference/README.md) 是合成静态设计资产，具有产品设计用途，可继续入库。部署配置、身份、地址与秘密只留私下，提交前扫描与人工核对见验证说明。
